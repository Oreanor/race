# City Rider

Игра о поездках по реальным городам в браузере и настольном приложении. Мир строится из векторных карт: дороги, здания, вода, рельеф и растительность. Есть автомобили, дорожный трафик, поезда, задания, топливо и сетевой режим.

Стек: Next.js 16, React 19, TypeScript, Three.js, Web Workers; настольная оболочка — Tauri 2. Для карт используется собственный движок `world3d`.

## Быстрый запуск

Нужны Node.js с поддержкой `--experimental-strip-types`, npm и браузер с WebGL 2. Последние проверки выполнялись на Node.js 26.13.0. Для загрузки карт и поиска мест нужен интернет.

```sh
npm install
npm run dev
```

Открыть [localhost:3000](http://localhost:3000). Dev-сервер слушает `0.0.0.0`, поэтому доступен и другим устройствам в локальной сети, если это разрешено сетевыми настройками компьютера.

Для проверки производительности использовать production-сборку:

```sh
npm run build
npm start
```

`build` использует webpack, `dev` — стандартный режим разработки Next.js. Не запускать сборку одновременно с dev-сервером в одном рабочем каталоге: они используют `.next`.

## Производительность и диагностика

Открыть [игру со статистикой](http://localhost:3000/?perf) или включить статистику в настройках. Панель показывает FPS, среднее и максимальное время кадра, CPU/GPU, draw calls, треугольники и инстансы.

Дополнительно показываются **пиковые CPU-затраты стадий за окно измерения**: игра, стриминг, сцена и LOD, слои, подготовка GPU, отрисовка и маркеры. Эти пики могут относиться к разным кадрам, поэтому складывать их нельзя. GPU-время доступно только при поддержке `EXT_disjoint_timer_query_webgl2`; прочерк означает отсутствие измерения.

Кнопка **«Бенчмарк»**, также **B** при включённой панели, синхронно проверяет отрисовку с ожиданием GPU. Она временно блокирует интерфейс и не измеряет полный игровой цикл с физикой и трафиком. Обычный FPS и результат этого теста напрямую не взаимозаменяемы.

Для воспроизводимого отчёта о фризе записать:

1. Город или координаты, положение и направление камеры.
2. Действие: первый поворот после загрузки, повторный поворот, открытие карты или прибытие в другой город.
3. Скрин статистики после задержки и сообщения консоли браузера.
4. Браузер, GPU, разрешение окна и режим запуска: dev или production.

Сравнивать первое посещение области с повторным отдельно: загрузка данных, подготовка GPU и кеши влияют на результат. Начальная готовность мира включает очередь подготовки GPU; это может увеличить время загрузки перед показом сцены.

Параметры адреса для проверки конкретного места:

```text
http://localhost:3000/?perf&at=-73.9857,40.7484&heading=90&time=12:00
```

`at` задаёт **долготу, широту**, `heading` — направление в градусах, `time` — время на часах выбранного места.

## Как устроен движок

| Путь | Ответственность |
| --- | --- |
| `src/components/Game.tsx` | Интерфейс, создание игры, выбор места, статистика |
| `src/game/GameEngine.ts` | Игровой цикл, физика, камера, задания и взаимодействия |
| `src/world3d/map/ThreeMap.ts` | Общая сцена Three.js, камера, освещение, отрисовка и подготовка GPU |
| `src/world3d/map/WorldTiles.ts` | План загрузки, очередь геометрии, видимость, выгрузка и восстановление worker |
| `src/world3d/tiles/world.worker.ts` | Загрузка данных и построение мира вне главного потока |
| `src/world3d/tiles/roadNetwork.ts` | Общая топология дорог, мостов и подходов; расчёт высот и переходов ширины |
| `src/world3d/tiles/roadSurface.ts` | Поперечные сечения полотна и точные треугольники поверхности для колёс |
| `src/world3d/tiles/roadTerrain.ts` | Рельеф соседних тайлов для общего расчёта дорожного профиля |
| `src/world3d/tiles/buildingAssembly.ts` | Связывание фрагментов зданий через границы тайлов и общий контекст фасадов |
| `src/world3d/tiles/buildTile.ts` | Геометрия зданий, крыши и раскладка окон |
| `src/world3d/map/facadeMaterial.ts` | Процедурные фасады, окна и архитектурные стили |
| `src/world3d/map/vegetation.ts` | Инстансинг и LOD растительности и декора |
| `src/world3d/perf/PerfMonitor.ts` | Сбор показателей кадра и бенчмарк |
| `src/rendering/` | Автомобили, поезда и визуальные эффекты |
| `src/game/TrafficBots.ts` | Дорожный граф и поведение ботов |
| `src/net/`, `server/` | Сетевой клиент, протокол и сервер |
| `src/config/` | Параметры камеры и автомобилей |
| `src/i18n/` | Локализация |
| `tests/fixtures/` | Данные карт для воспроизводимых тестов |

Данные мира приходят тайлами. Worker строит геометрию и передаёт typed arrays в основной поток; основной поток постепенно создаёт меши и готовит буферы GPU. Здания и растительность используют пакетную геометрию и инстансинг. Плавающее начало координат сохраняет точность при перемещении по миру.

Дороги, мосты и подходы рассчитываются как один граф: в соединении существует одна высота, а не два независимо исправляемых конца. Ограничения просвета и уклона распространяются по всему графу до сходимости. Покрытие, плита и парапеты используют общие поперечные сечения; физика выбирает высоту по тем же треугольникам, с учётом текущего уровня машины. Индекс этих треугольников готовится в worker. Смена ширины получает плавный переход. Данные OSM не задают точную высоту каждого моста: уровни и пересечения остаются основой приближения. Если длины подхода недостаточно для просвета при обычном уклоне 8%, расчёт допускает больший уклон только в этом противоречивом цикле.

Для здания на границе тайлов сборка следует по совпадающим отрезкам контура в соседние тайлы. Связанные фрагменты получают общий ключ стиля и непрерывную раскладку окон. Одного ID источника недостаточно: векторные данные могут объединять разные дома в одну запись. Геометрия для отрисовки остаётся разделённой на части. Крыши пока рассчитываются по отдельным фрагментам. Одна сборка ограничена 64 исходными тайлами.

## Сетевой режим

В двух терминалах запустить игру и сервер:

```sh
npm run dev
```

```sh
npm run server
```

Открыть [localhost:3001](http://localhost:3001). Этот адрес проксирует игру с порта 3000 и обслуживает WebSocket `/mp`.

| Переменная | Назначение |
| --- | --- |
| `MP_PORT` | Порт сервера, по умолчанию 3001 |
| `MP_NEXT_HOST` | Хост Next.js, по умолчанию `127.0.0.1` |
| `MP_NEXT_PORT` | Порт Next.js, по умолчанию 3000 |
| `MP_MAX_PLAYERS` | Лимит подключений, по умолчанию 100 |
| `NEXT_PUBLIC_MP_URL` | Адрес WebSocket; `off` отключает сетевой режим |

Переменные `NEXT_PUBLIC_*` для production задаются перед сборкой. Настройка туннеля, публикации его адреса и серверные ограничения описаны в [документации multiplayer](docs/multiplayer.md). Секреты и локальные `.env`-файлы в репозиторий не добавлять.

## Настольная версия

Для Tauri дополнительно нужны Rust и системные инструменты сборки. На Windows — инструменты C++ для сборки Rust-приложений и WebView2. Конфигурация находится в `src-tauri/tauri.conf.json`; текущая цель установщика — NSIS.

```sh
npm run tauri:dev
npm run tauri:build
```

Tauri сам запускает нужную команду подготовки фронтенда. Production-версия содержит статический сайт из `out`, без встроенного Node.js-сервера и Next API routes. Поэтому сетевые API необходимо учитывать отдельно; настольная оболочка не делает картографические данные автономными.

`build:desktop` временно переименовывает API routes и восстанавливает их в `finally`. После принудительного завершения процесса проверить, не остались ли файлы `*.desktop-bak`, прежде чем продолжать веб-разработку.

## Проверки и известные ограничения

```sh
npm run typecheck
npm test
```

Для изменений мира можно отдельно выполнить:

```sh
node --experimental-strip-types --test tests/world3d.test.ts tests/buildings.test.ts tests/vegetation.test.ts
```

На последнем полном прогоне оставались три падающих теста сцепления в `tests/physics.test.ts`: тесты ожидают накопление оборотов и старт со сцепления, тогда как Shift реализован как ручник. Это известное расхождение тестов и текущего управления.

Фризы первых поворотов и быстрых перемещений ещё требуют проверки в игре на разных GPU. Успешные тесты и сборка не подтверждают плавность отрисовки или отсутствие предупреждений драйвера. Изменения процедурных окон следует проверять на нескольких GPU: ранее наблюдались артефакты, похожие на телевизионные помехи.
