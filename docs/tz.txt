# Техническое задание: City Rider

## 1. Концепция

Разработать браузерное 3D-приложение на Next.js, позволяющее пользователю свободно кататься на автомобиле по реальным городам мира.

Город генерируется автоматически на основе географических данных MapLibre и OpenStreetMap. Здания отображаются в виде стилизованных разноцветных 3D-объёмов, дороги соответствуют реальной уличной сети.

Игрок управляет автомобилем с помощью WASD. Камера располагается позади автомобиля, свободно вращается мышью и поддерживает приближение и отдаление.

Визуальная концепция — яркая, аккуратная, слегка игрушечная трёхмерная карта города. Фотореализм не требуется.

Приложение должно запускаться непосредственно в браузере, без авторизации и установки дополнительного ПО.

## 2. Технологический стек

- Next.js 15+ с App Router.
- TypeScript, strict mode.
- React.
- MapLibre GL JS 6+ — карта, здания, дороги, рельеф, управление географической камерой.
- Three.js — загрузка и рендер автомобиля.
- GLTFLoader — загрузка GLB/GLTF.
- OpenFreeMap — векторные картографические данные.
- OpenStreetMap — географические данные.
- DEM-источник, совместимый с MapLibre, для рельефа.
- Tailwind CSS — интерфейс.
- requestAnimationFrame — игровой цикл.

Не использовать Cesium, Google Maps, Unity, Unreal Engine и обязательные платные API.

Для интеграции Three.js использовать MapLibre CustomLayerInterface с `renderingMode: "3d"` и общим WebGL-контекстом. Не создавать независимый Three.js canvas поверх карты в качестве основного решения.

Картографический провайдер должен быть заменяемым через конфигурацию.

## 3. Стартовый экран и выбор города

При запуске отображается экран выбора города.

Функциональность:

- Выпадающий список городов с поиском по названию.
- Начальный набор: Coimbra, Lisbon, Porto, Paris, London, New York, Tokyo.
- Кнопка **Drive**.
- Загрузка необходимого участка карты и 3D-модели.
- После загрузки игрок появляется на автомобиле в центральной части выбранного города.

Для MVP использовать локальный конфигурационный список городов с названием, координатами центра, координатами точки старта и начальным направлением автомобиля.

Точка старта должна находиться непосредственно на дороге, а не внутри здания или на городской площади.

Архитектура должна позволять в будущем подключить геокодирование и поиск произвольных городов.

При смене города игровая сцена корректно переинициализируется без перезагрузки страницы.

## 4. Отображение города

### 4.1. Карта

Использовать MapLibre GL JS и векторные тайлы OpenFreeMap.

Карта должна содержать:

- Реальную уличную сеть.
- Объёмные здания.
- Парки и зелёные зоны.
- Реки и водоёмы.
- Мосты.
- Трёхмерный рельеф местности, где доступны данные высот.

Геометрия города должна подгружаться динамически по мере движения.

Не ограничивать поездки одним заранее подготовленным квадратом карты.

### 4.2. Здания

Здания строить через `fill-extrusion` по данным из векторных тайлов.

Использовать реальную высоту здания, если она присутствует в данных. При отсутствии высоты задавать разумную высоту по умолчанию.

Предусмотреть несколько цветовых палитр:

- Pastel — пастельные оттенки.
- Vibrant — насыщенные цвета.
- Minimal — светлые нейтральные здания.
- Dark — тёмные здания с цветными акцентами.

В базовом варианте использовать пастельную палитру из 5–8 оттенков.

Здания должны получать стабильную окраску: при перемещении камеры или повторной загрузке тайла цвет здания не должен случайно изменяться.

Для этого применять детерминированные правила по данным объекта или его стабильному идентификатору, если он доступен.

### 4.3. Дороги

Дороги должны визуально отличаться от окружающей поверхности.

- Асфальт — нейтральный тёмно-серый.
- Второстепенные дороги — более светлые.
- Пешеходные дорожки — отдельный цвет.
- Разметка — если доступна из стиля или добавлена собственными слоями.

Не генерировать текстуры дорог вручную на первом этапе.

### 4.4. Рельеф

Использовать terrain API MapLibre с raster-dem источником.

Автомобиль должен находиться на уровне поверхности, а не на условной нулевой высоте.

Применять `queryTerrainElevation()` и корректную привязку Three.js-модели к географической высоте.

Если данные высоты недоступны, использовать нулевую высоту как fallback.

Не допускать резкого подпрыгивания машины при запоздалой подгрузке DEM.

## 5. Автомобиль

### 5.1. 3D-модель

Модель автомобиля загружать из файла:

`/public/models/car.glb`

Использовать Three.js GLTFLoader.

Требования:

- Поддержка стандартных GLB-моделей.
- Возможность настройки масштаба.
- Возможность исправления начального направления модели.
- Правильное положение относительно дороги.
- Сохранение пропорций модели.
- Корректная работа PBR-материалов.
- Базовое освещение для читаемости модели.

Настройки масштаба, ориентации и вертикального смещения должны находиться в отдельной конфигурации, без изменения исходного GLB.

Если GLB не загрузился, показывать простую процедурную модель автомобиля, чтобы приложение оставалось работоспособным.

### 5.2. Перемещение

Автомобиль перемещается в реальных географических координатах.

Игровую физику рассчитывать в локальной системе координат, в метрах, с преобразованием в географические координаты для отображения на карте.

Не рассчитывать скорость и перемещения путём непосредственного прибавления одинаковых значений к широте и долготе.

При длительном перемещении предусмотреть возможность переноса локального начала координат, чтобы избежать потери точности.

## 6. Управление автомобилем

| Клавиша | Действие |
|---|---|
| W | Газ |
| S | Тормоз / задний ход |
| A | Поворот влево |
| D | Поворот вправо |
| Space | Ручной тормоз |
| R | Вернуть стандартную камеру |

Реализовать простую аркадную физику:

- Плавный разгон.
- Плавное торможение.
- Ограничение максимальной скорости.
- Инерция при отпускании газа.
- Повороты с учётом текущей скорости.
- Разворот и движение задним ходом.
- Более сильное замедление при ручном тормозе.
- Плавное изменение направления автомобиля.

Начальные параметры:

- Максимальная скорость вперёд: 90 км/ч.
- Максимальная скорость назад: 25 км/ч.
- Ускорение: 7 м/с².
- Торможение: 12 м/с².

Все параметры вынести в `vehicle.config.ts`.

**Не использовать полноценный физический движок в MVP.** Реализовать кинематическую аркадную модель движения с фиксированным шагом симуляции.

Машина должна реагировать на комбинации клавиш, например W+A.

Нажатия клавиш должны отслеживаться независимо от частоты React-рендеров.

Не использовать React state для обновления положения машины на каждом игровом кадре.

## 7. Камера от третьего лица

Это один из ключевых модулей приложения.

### 7.1. Начальное положение

Камера находится позади автомобиля, немного выше него, направлена на машину.

Начальные параметры:

- Расстояние: приблизительно 14 метров.
- Высота: приблизительно 7 метров.
- Цель: центральная точка автомобиля с небольшим вертикальным смещением.
- Плавное слежение за движением.

Машина должна находиться приблизительно в нижней центральной части экрана, чтобы впереди оставалось достаточно пространства для обзора дороги.

### 7.2. Управление камерой

- **Правая кнопка мыши + движение:** вращение камеры вокруг автомобиля по горизонтали и вертикали.
- **Колесо мыши:** приближение и отдаление.
- **R:** восстановление стандартного ракурса.

Ограничения:

- Минимальное расстояние — около 5 метров.
- Максимальное расстояние — около 50 метров.
- Нельзя опустить камеру ниже поверхности дороги.
- Нельзя перевернуть камеру вверх ногами.

При обычном движении камера плавно следует за автомобилем.

После ручного вращения камера сохраняет выбранный пользователем угол. Автоматическое возвращение за машину можно включать отдельной опцией.

Поворот автомобиля не должен вызывать мгновенный резкий поворот камеры.

Использовать сглаживание на основе deltaTime, а не фиксированный коэффициент на кадр.

### 7.3. Реализация

Камера должна использовать географическую камеру MapLibre.

Рассмотреть `FreeCameraOptions` и `setFreeCameraOptions()` для задания положения камеры в пространстве и ориентации на автомобиль.

Если используется стандартная камера MapLibre, корректно синхронизировать center, bearing, pitch и zoom.

Вращение мышью не должно одновременно включать стандартный dragRotate или dragPan карты.

Избегать конкурирующих анимаций MapLibre и собственного игрового цикла.

## 8. Игровой цикл

Реализовать единый игровой цикл на `requestAnimationFrame`.

Разделить:

1. Чтение ввода.
2. Обновление физического состояния автомобиля.
3. Расчёт новой позиции и ориентации.
4. Определение высоты поверхности.
5. Обновление трансформации GLB-модели.
6. Обновление камеры.
7. Запрос перерисовки карты при необходимости.
8. Обновление HUD с ограниченной частотой.

Для физики использовать фиксированный timestep, например 1/60 секунды, с аккумулятором времени.

Для визуальных обновлений использовать интерполяцию между состояниями симуляции при необходимости.

При переключении вкладки, потере фокуса или большом скачке deltaTime не допускать резкого перемещения автомобиля.

## 9. Интерфейс

Интерфейс минималистичный, игровой, без лишних панелей.

### Стартовый экран

- Название City Rider.
- Выбор города.
- Кнопка Drive.

### Игровой экран

- Карта на весь экран.
- Название текущего города в левом верхнем углу.
- Кнопка смены города.
- Компактный спидометр в км/ч.
- Кнопка настроек.
- Индикатор загрузки тайлов и модели.

### Настройки

- Выбор цветовой палитры зданий.
- Чувствительность камеры.
- Автоматическое следование камеры за направлением машины.
- Громкость (резерв для будущих звуков).
- Качество отображения / разрешение рендеринга, если поддерживается.

Первоначально ориентироваться на desktop. Сенсорное управление на смартфонах не требуется.

## 10. Столкновения и дороги

В MVP автомобиль должен свободно двигаться, не будучи привязанным к маршруту навигатора или центральной линии дороги.

**Не применять автоматическое следование по дорогам (road snapping) во время движения.** Пользователь управляет машиной самостоятельно.

На первом этапе разрешить выезд с дороги.

Коллизии со зданиями не обязательны для самого первого работоспособного прототипа, но архитектура должна предусматривать их добавление.

Важно: `fill-extrusion` — визуальная геометрия карты, а не готовый физический коллайдер.

Для последующей реализации столкновений использовать отдельные географические контуры зданий и локальные упрощённые коллайдеры.

Не пытаться использовать один только `queryRenderedFeatures()` как готовый физический движок.

## 11. Архитектура проекта

Предлагаемая структура:

```text
src/
  app/
    page.tsx
    layout.tsx
    globals.css

  components/
    game/
      Game.tsx
      GameMap.tsx
      GameHUD.tsx
      CitySelector.tsx
      SettingsPanel.tsx

  game/
    GameEngine.ts
    InputController.ts
    VehicleController.ts
    CameraController.ts
    TerrainController.ts
    CoordinateSystem.ts
    GameLoop.ts

  map/
    createMap.ts
    buildingLayers.ts
    mapStyles.ts
    terrain.ts
    cities.ts

  rendering/
    VehicleLayer.ts
    ModelLoader.ts

  config/
    vehicle.config.ts
    camera.config.ts

  types/
    game.ts

public/
  models/
    car.glb
```

Названия файлов можно адаптировать, сохранив разделение ответственности.

### Принципы архитектуры

- MapLibre отвечает за географическую карту и её камеру.
- Three.js отвечает за 3D-модель автомобиля.
- GameEngine координирует движение, камеру и рендеринг.
- VehicleController не зависит от React.
- CameraController не зависит от конкретной GLB-модели.
- Географические преобразования вынести в отдельный модуль.
- React отвечает за UI и жизненный цикл приложения.
- Не создавать новый MapLibre instance при каждом обновлении состояния.
- Корректно освобождать WebGL-ресурсы, event listeners и requestAnimationFrame при размонтировании.

Компонент карты должен работать только на клиенте, без SSR-зависимостей от `window` или `document` при серверном рендеринге.

## 12. Этапы реализации

### Этап 1 — карта

- Создать Next.js-проект.
- Подключить MapLibre.
- Реализовать выбор города.
- Отображать карту с 3D-зданиями.
- Добавить пастельную палитру зданий.
- Настроить первоначальный игровой угол камеры.

**Результат:** трёхмерный стилизованный город в браузере.

### Этап 2 — автомобиль

- Добавить Three.js через MapLibre custom layer.
- Загрузить GLB.
- Разместить автомобиль в стартовой точке.
- Проверить масштаб, ориентацию, глубину и синхронизацию с картой.
- Сделать процедурную fallback-модель.

**Результат:** настоящий трёхмерный автомобиль стоит на улице.

### Этап 3 — движение

- Реализовать игровой цикл.
- Добавить WASD.
- Разгон, торможение, повороты.
- Географические преобразования координат.
- Спидометр.

**Результат:** автомобиль может свободно ездить по карте.

### Этап 4 — камера

- Следящая камера от третьего лица.
- Вращение правой кнопкой мыши.
- Зум колесом.
- Плавное следование.
- Возврат к стандартному ракурсу.

**Результат:** полноценная управляемая камера автомобильной аркады.

### Этап 5 — рельеф и полировка

- Подключить DEM.
- Синхронизировать высоту машины с рельефом.
- Добавить простую коррекцию наклона машины в зависимости от поверхности, если возможно без нестабильности.
- Добавить цветовые темы.
- Оптимизировать производительность.
- Добавить обработку загрузок и ошибок.

**Результат:** законченный игровой прототип.

После каждого этапа проверять, что проект запускается и предыдущая функциональность не сломана.

## 13. Производительность

Цель — плавная работа на обычном desktop-компьютере с WebGL2.

- Целевые 60 FPS на умеренном количестве 3D-зданий.
- Минимально приемлемые 30 FPS в плотном городе.
- Не перерисовывать React-компоненты на каждом кадре.
- Использовать только необходимые географические тайлы.
- Не загружать GLB повторно при обычном движении.
- Не пересоздавать Three.js renderer или материалы без необходимости.
- Обрабатывать временное отсутствие сетевых данных.
- Не блокировать интерфейс на время загрузки соседних тайлов.

## 14. Критерии приёмки MVP

Приложение считается работоспособным, если:

- [ ] Запускается через `npm run dev`.
- [ ] Успешно собирается через `npm run build`.
- [ ] Можно выбрать минимум три разных города.
- [ ] Появляется реальная карта выбранного города.
- [ ] Здания отображаются объёмными и цветными.
- [ ] На дороге видна 3D-модель автомобиля.
- [ ] Автомобиль двигается по WASD с плавной аркадной физикой.
- [ ] При движении автомобиль сохраняет правильное направление и масштаб относительно карты.
- [ ] Камера плавно следует за машиной.
- [ ] Камера вращается правой кнопкой мыши.
- [ ] Колесо мыши меняет расстояние до автомобиля.
- [ ] Клавиша R восстанавливает стандартный ракурс.
- [ ] Спидометр показывает текущую скорость.
- [ ] Смена города корректно перемещает автомобиль и камеру.
- [ ] Включение рельефа не заставляет машину проваливаться под землю.
- [ ] Нет критических ошибок JavaScript и утечек ресурсов при повторной смене города.

## 15. Что не нужно делать

Не добавлять без отдельного запроса:

- Мультиплеер.
- Регистрацию пользователей.
- Серверную базу данных.
- Покупку автомобилей.
- Гонки, чекпоинты и миссии.
- NPC и дорожный трафик.
- Сложную физику подвески.
- Повреждения автомобилей.
- Генерацию фотореалистичных текстур.
- Отдельный редактор карт.
- Мобильные виртуальные джойстики.

Приоритет — законченный, удобный и визуально приятный минимальный прототип.

При выборе архитектурных решений отдавать предпочтение простоте, поддерживаемости и реальной работоспособности API.
