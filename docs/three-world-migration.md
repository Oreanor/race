# three-world: отказ от MapLibre в пользу собственной Three.js-сцены

Статус: этап 1 готов (здания, стриминг тайлов, машина, камера, коллизии со зданиями, профилирование).
Старый режим не тронут и остаётся основным. Переключение: `/?mode=three-world` или переключатель в шапке.
Замеры в MapLibre-режиме: `/?perf=1`.

## Что MapLibre делает сейчас

Весь город, растительность, машина и эффекты уже рисуются через Three.js в custom-слоях
(`CityBuildings`, `VegetationLayer`, `VehicleLayer`). Каждый слой создаёт свой `WebGLRenderer`
на общем контексте и рендерит свою сцену каждый кадр, с `resetState()` до и после.
Сам MapLibre отвечает за следующее.

| Функция | Где используется | Замена в three-world |
|---|---|---|
| Загрузка и декодирование PBF (OpenFreeMap) | `querySourceFeatures` в `GameEngine`, `roadStart`, `TrafficBots` | `world3d/tiles/*`: воркеры + `buildTile` (сделано для зданий) |
| Отрисовка дорог, воды, земли, подписей | стиль `liberty`, `paintCity` | этап 2–3: свои меши дорог и воды из тех же тайлов |
| Рельеф: DEM-тайлы, `queryTerrainElevation` (14 вызовов), `setTerrain`, hillshade | здания, растительность, машина | этап 4: свой загрузчик terrarium DEM + сэмплер высот |
| Камера: `jumpTo`, zoom/pitch/bearing, `zoomForDistance` | `GameEngine` | `world3d/ChaseCamera` (сделано) |
| Проекция: `project`/`unproject`, `MercatorCoordinate` | прицел, маркеры, слои | `world3d/mercator.ts` (`LocalFrame`, плавающее начало координат) |
| HTML-маркеры (`maplibregl.Marker`) | миссии, финиш, спавн | этап 5: проекция камеры Three.js + DOM |
| Клик по карте для выбора спавна | `map.on('click')` | этап 5: raycast по земле |

## Замеры (Коимбра, 1920×918, Intel Arc 130V, Chrome)

Метрики снимаются одним и тем же `PerfMonitor`: он оборачивает draw-вызовы WebGL-контекста.
Поэтому draw calls и треугольники в обоих режимах посчитаны одинаково. «Бенчмарк» синхронно рендерит
90–120 кадров и после каждого ждёт GPU (`readPixels`). Это стоимость кадра без ограничения vsync.

| Режим | Draw calls/кадр | Треугольники/кадр | Стоимость кадра (бенчмарк) | ≈ FPS без vsync |
|---|---|---|---|---|
| MapLibre, стартовый экран | 494 | 2,17 M | 12,5 мс | ~80 |
| MapLibre, езда | 407–482 | 3,0–3,3 M | 23–32 мс | ~31–43 |
| three-world, езда, окна текстурой | 26 | 0,25 M | 4,0 мс (p95 6,2) | ~250 |
| three-world, гибрид (instancing вблизи) | 32 | 0,54 M | 4,6 мс | ~220 |
| three-world, instancing везде | 50 | 1,15 M | 4,8–5,6 мс | ~180–210 |

Сравнение не «одна и та же сцена». MapLibre-режим дополнительно рисует дороги, воду, рельеф,
деревья, подписи и детальные фасады из `BuildingManager`. Цифры показывают потолок выигрыша
на текущем этапе. Его нужно перепроверять по мере переноса систем.
Разница на порядок в draw calls объясняется архитектурой (чанки по 1 вызову против множества
слоёв и сцен), а не меньшим числом зданий: three-world держит в памяти ~17–20 тыс. зданий
в радиусе 1,5 км.

## Как устроен three-world

- `mercator.ts`: Web Mercator, тайловая математика и `LocalFrame` (плавающее начало координат).
  Геометрия тайла хранится относительно его угла в «меркаторных метрах», группа тайла масштабируется
  на `cos(lat)` начала координат. При удалении машины на 2 км начало переносится, а тайлы только
  перемещаются, без пересборки.
- `tiles/buildTile.ts`: PBF → обрезка по границе тайла (без ложных стен на швах) → стены, плоские
  крыши (earcut), UV фасада, компактные инстансы окон (8 float на окно), контуры для геймплея.
  Чистая функция, покрыта тестами на фикстуре Коимбры.
- `tiles/tile.worker.ts` + `TileClient.ts`: пул module-воркеров, отмена запросов, фолбэк в main thread.
- `tiles/TileManager.ts`: план тайлов вокруг машины с упреждением по скорости, гистерезис
  загрузки и выгрузки (1500/2300 м), лимит параллельных запросов, LRU-кеш данных, загрузка в GPU
  по 3 чанка за кадр, отсечение по дальности, LOD окон, `footprintsNear()` для коллизий.
- `buildings/materials.ts`: один шейдер на стены и крыши чанка (окна из маски-текстуры,
  цвета Portuguese Pastel в вершинах), instanced-окна, земля с сеткой. Лампы на здания не влияют.
- `ThreeWorld.ts`: рендерер, физика `VehicleController` (без изменений), `BuildingCollisions`
  (без изменений, кормится контурами из тайлов), GLB-машина, `ChaseCamera`, профилирование.

## Порядок миграции

1. **Готово.** Здания, тайлы, камера, машина, коллизии со зданиями, профилирование, сравнение.
2. Дороги: линии `transportation` → ленты по ширине класса, батчинг в те же чанки. Дать
   `roadStart`/`TrafficBots`/миссиям источник фич, не зависящий от `querySourceFeatures`
   (адаптер с тем же форматом `MapFeature`).
3. Вода и земля: `water`/`landcover`/`landuse` → плоские меши, `WaterCollisionController` на тех же данных.
4. Рельеф: terrarium DEM напрямую, сэмплер высот вместо `queryTerrainElevation`, смещение вершин
   зданий и земли.
5. Перенос `CityBuildings` (детальные фасады, `BuildingManager`), `VegetationLayer`, `VehicleLayer`
   с MapLibre custom-layer на обычные `THREE.Scene` в одном рендерере: убрать двойной
   `resetState()` и три рендерера на одном контексте.
6. Маркеры, прицел, выбор спавна кликом, подписи улиц.
7. Повторить сравнение FPS на одинаковом наборе систем и только после этого решать, удалять ли MapLibre.

## Известные ограничения этапа 1

- Нет дорог, воды и рельефа: машина ездит по плоской земле, спавн сдвигается с контура здания на свободное место.
- Нет прозрачности зданий, перекрывающих машину (в MapLibre-режиме это делает `buildingFade`).
- В OpenFreeMap на z14 много зданий слиты в один MultiPolygon, поэтому цвет выбирается по позиции
  здания, а не по `feature.id`. Конкретные цвета не совпадают с MapLibre-режимом, палитра та же.
- Бенчмарк MapLibre вызывает `map.redraw()`; GPU-время по таймер-запросам есть только в three-world.

## Этап 2 (сделан): игра целиком на собственном движке

`?mode=` выбирает рендерер: по умолчанию `three` (игра на нашем движке), `maplibre` (старый, для сравнения), `three-world` (лаборатория рендера).

Как устроено: `world3d/map/ThreeMap.ts` — тонкий адаптер с тем подмножеством API `maplibregl.Map`, которое реально вызывает игра
(камера 1:1 с MapLibre, `querySourceFeatures`, `queryTerrainElevation`, маркеры, события). `GameEngine`, `CityBuildings`,
`VegetationLayer`, `VehicleLayer` не переписаны. Под ними:
- `tiles/world.worker.ts` — PBF + DEM одного тайла в одной задаче: земля (меш по DEM + растр землепользования/воды/дорог),
  ленты дорог, дальние здания (батч, одна отрисовка на чанк), GeoJSON для игры, сырые байты PBF;
- `map/WorldTiles.ts` — стриминг, LOD дорог, «дырка» для дальних зданий там, где детальный слой уже построил дома.

### Костыли MapLibre: что исчезло
- перекраска стиля `liberty` (`paintCity`), скрытый-но-видимый слой `building` ради `querySourceFeatures`;
- копирование воркера MapLibre в `public/vendor` (нужно только для режима `maplibre`);
- смена детализации DEM с зумом → в новом движке один DEM-уровень, высоты не меняются, здания не «переседают»;
- три Three.js-слоя теперь получают единый контекст и одну камеру нашего рендерера;
- POI (АЗС, порты, аэропорты) доступны напрямую — в MapLibre их скрывал стиль.

### Костыли, которые остаются (следующие шаги)
- `zoomForDistance` и «зум» камеры — заменить на камеру в метрах;
- периодическое пере-чтение всех фич (`collectWorldSteps`, `collisionDirty`, дедупликация копий `collapseCopies`) —
  заменить на события «тайл пришёл / ушёл» с уже уникальными зданиями;
- `CityBuildings.reveal` / `VehicleLayer.cameraPose` вычисляют позу камеры из zoom/pitch — брать у камеры напрямую;
- по `WebGLRenderer` на каждый слой + `resetState()` — свести в одну сцену;
- происхождение (origin) `CityBuildings` фиксировано в точке старта: поэтому перелёт = перезапуск движка с переносом игрока.

### Замеры (Коимбра, 1920×918, Intel Arc 130V, GPU-таймеры)
- базовый мир: 5,1 мс GPU, из них дороги 2,3 мс → после LOD и упрощения стыков треугольников дорог вдвое меньше;
- `CityBuildings` 3,8 мс GPU, растительность 0,4, машины 0,3;
- полный кадр без vsync до оптимизации дорог: ~26 мс — на уровне MapLibre (23–32 мс). Выигрыш «в разы», как в лаборатории,
  появится после сведения слоёв в одну сцену и облегчения детального слоя — это следующий шаг, не уже достигнутый результат.

## Геймплей поверх данных карты
- Топливо (`game/Fuel.ts`): бак и расход у каждой машины, реальные АЗС (`poi`, `class=fuel`, без зарядок EV), 1 монета/л,
  пустой бак → эвакуатор на ближайшую АЗС за 100 монет (+10% бака, чтобы не застрять без денег).
- Порты и аэропорты (`game/Travel.ts`): `aerodrome_label` + паромные терминалы; билет в любой город,
  цена = км × тариф (порт 1, аэропорт 1,5 монеты/км), деньги и топливо переносятся.

## Общий мир и сервер (заложено, не сделано)
Позиция игрока везде — глобальные lng/lat, сцена с плавающим началом координат. Для сервера: WebSocket-комната на
тайл z10–z12, игрок рассылает позу ~10 Гц, получает соседей по своим и соседним тайлам; поиск друга = запрос его
позиции → перелёт/телепорт туда. Друзья и авторизация — отдельно.

## Этап 3 (сделан): одна система на каждый тип объектов

Правило проекта: в кадре ничего не появляется и не исчезает, никаких прореживаний (лимитов растений, «ближних N домов»).

- Дома: только батч-чанки из тайлов (`CityBuildings` в режиме `three` не создаётся). Окна — маской на всех дистанциях.
  Дома между камерой и машиной — мягкая прозрачность дизерингом в шейдере. Коллизии и попадания пуль — по контурам из тайлов.
- Растительность и заборы парков: планируются в воркере по тайлу один раз и полностью (те же правила посадки, без лимита),
  рисуются instancing'ом по тайлу. Старый `VegetationLayer` остаётся только для MapLibre.
- Тайлы грузятся до 2,8 км, туман сплошной с 2 км: всё новое приходит невидимым. Мир показывается, когда загружено всё видимое.
- Тик игры больше не перечитывает и не дедуплицирует дома: коллизии берутся из контуров ближайших тайлов.

Замер (Коимбра, 1920×~990, Intel Arc 130V, синхронный рендер с GPU-таймером):
MapLibre-режим — GPU 12,2 мс, CPU отрисовки 12,9 мс; наш — GPU 3,1 мс, CPU отрисовки 1,6 мс, 71 draw call базовой сцены.

Дальше: вернуть детали фасадов (скатные крыши, балконы, карнизы — в воркере, instancing), свести слои машин и АЗС
в общую сцену, ускорить сборку тайла (сейчас ~2,4 с в воркере, в основном растительность).
